# QA Checklist

## 必过项

- 是 16:9 横版。
- 背景是干净白底。
- 极简黑白线稿：细黑线、角色身体内部留白、无阴影无渐变无材质。
- 猫是简笔画角色（空心椭圆身体、小黑点眼、火柴棍腿），不是写实猫。
- 有三花猫。
- 三花猫承担核心动作，不只是装饰。
- 没有复刻旧案例构图，而是为当前文章生成了新隐喻。
- 画面怪诞、有创意、有意思。
- 简洁清爽，主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读。
- 橙色只用于主路径或箭头。
- 红色只用于重点、问题、提醒或结果。
- 蓝色只用于补充说明、反馈或系统状态。

## 失败信号

出现以下情况，重生成或局部编辑：

- 左上角有“常见坑 / Workflow / 系统架构图 / 路线图”等标题。
- 三花猫像吉祥物、表情包或可爱卡通。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 画面太死板，没有荒诞隐喻。
- 和 `assets/examples/` 里的旧案例构图过于相似。

## 迭代方法

- 太普通：让三花猫成为动作主体，加入一个奇怪但成立的隐喻。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 太可爱：强调 deadpan、blank serious expression、not cute、not mascot。
- 画风写实（毛发、阴影、体积感、绿眼睛）：用 edit 执行 prompt-template 里的"风格跑偏成写实时"指令，或重生成并在提示词里强调"身体内部留白、小黑点眼睛、火柴棍腿、不要毛发纹理"。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成手绘场景。
- 太像旧案例：保留核心意思，换掉主物件和三花猫动作。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。

## 交付判断

高质量图应该让读者先觉得“有点怪”，然后 1 秒内看懂结构。

如果第一眼像教程页，而不是白纸上的怪诞产品草图，就不合格。

## 角色一致性（三花猫）

- 必须保留三花特征：身体上一小块黑色填充色块 + 尖耳 + 白嘴周轮廓，让读者认出是这只猫。
- 眼睛是小黑点（和原版小黑白点眼同级），不是写实绿眼。
- 冷淡脸、不卖萌；若太可爱，用 edit 命令以 `assets/cat/cat-01.png` 为参考图重做（strength 0.6 起）。
